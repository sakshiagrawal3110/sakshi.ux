Building a scalable design system for a global financial brand

Transforming fragmented UI patterns into a scalable, accessible design system built to support global digital experiences, multiple markets and evolving business needs.

Scope

Timeline

12+ months

I led the design-system initiative within the UX team, establishing the foundations, components and interaction patterns needed to create a more consistent and scalable digital experience. I worked across UX, Brand, Marketing, Accessibility, Development and global stakeholders to translate business and user requirements into reusable design patterns and system rules.

The Problem

Components existed. The rules didn't.

The design system had accumulated reusable UI patterns over time, but many had evolved around individual page and business requirements rather than a shared system. Similar experiences could therefore require different design decisions, creating unnecessary variation and making the system harder to scale.

01 - Rebuilding the Foundation

Rebuilding the foundation before rebuilding the components

Before expanding the component library, we established a shared visual foundation that could support the system consistently across experiences.

We deliberately reserved #165EDA as the system's activation colour. Rather than using blue simply as another brand colour, we used it to identify things users could interact with-links, buttons, active navigation, expandable states and interactive text. This turned colour into a functional part of the design system.

02 - Designing One System

One system across screens and markets

The system needed to work across a global website ecosystem rather than a single product or screen size. We established a consistent 12 / 24 / 36 / 48 spacing scale and defined reusable layout behaviour for components across desktop, tablet and mobile experiences.

03 - Buttons

From visual variations to system rules

The challenge wasn't simply to reduce the number of buttons. It was to establish a clear logic for why each treatment existed and when it should be used. We reframed the component around three decisions: Intent, Variant, and State. We moved from a library of visual options to a system of decisions.

04 - One Component, Multiple Experiences

Separating content from structure

Rather than creating a new component for every content type, we defined a shared component structure that could adapt through controlled properties. By separating content requirements from component structure, we could create different experiences without creating a new component every time the content changed.

06 - Accessibility

Accessibility became part of the system

Accessibility wasn't treated as a final quality check. It became part of how components and experiences were designed from the beginning. By building accessibility into reusable components, every subsequent experience started from a stronger baseline.

07 - Governance

A design system isn't finished when published

As new requirements emerged, the system needed a mechanism for deciding what should be added, changed or rejected. We established recurring UX Open Houses as a forum for designers to bring new requirements, explore patterns and align on system decisions.

Outcome

A system designed to scale, not just standardise

The result was a more scalable foundation for design and implementation, stronger accessibility practices and a shared visual language that extended beyond UX into marketing and brand experiences.

The goal wasn't to build 50 components. It was to make the 51st easier to build well.

Design System: The Short Version

  • The Problem: The digital ecosystem had accumulated fragmented UI patterns over time, lacking shared rules, responsive consistency, and embedded accessibility.
  • The Solution: Instead of adding more components, we paused to establish core foundations (typography, spacing, activation colors) and rebuilt the system around intentional design decisions rather than visual options.
  • Governance: Established recurring UX Open Houses to create a continuous feedback loop, turning the design system from a static library into a living product.
