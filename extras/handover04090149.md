# Handover Document

## 1. Project / Goal Overview
- **Goal:** The user, Sakshi (a Product Designer), is building a highly polished, responsive, and interactive UX Designer portfolio website.
- **Objectives:** The portfolio relies on a complex "bento-box" masonry grid layout on the home page leading into deep, immersive case study pages. The primary objective is to achieve a premium, dynamic, and fluid "Framer-style" aesthetic natively in the browser.
- **Success Criteria:** A flawlessly interlocking masonry grid with zero empty gaps and a perfectly flush bottom edge; unified tactile interaction states (springy physics, hover arrows, click-squish); native, app-like page transitions (cards expanding into hero banners and collapsing back); and seamless video backgrounds with custom gradient masking.

## 2. Context & Background
- **Situation:** The user has iteratively refined the portfolio from a static layout into a highly dynamic experience. The most recent focus has been on implementing native, app-like page transitions between the index tiles and the case study pages, mimicking an "App Store" expansion effect, as well as embedding video backgrounds with frosted glass edge-blending.
- **Technologies:** Pure HTML, CSS, and Vanilla JavaScript.
- **Constraints:** Absolutely no heavy external JavaScript frameworks (no React, no Framer Motion, no Barba.js). 
- **External Factors:** The user provides video references (e.g., Jitter.video exports, specific UI interaction recordings) and expects precise code implementations that match the visual fidelity and physical motion curves of the references.

## 3. Decisions Made
- **Self-Contained Architecture:** Deprecated external `styles.css` files. All styles and JavaScript are embedded directly within the `<style>` and `<script>` blocks of their respective HTML files to keep them portable and self-contained.
- **View Transitions API:** Decided to use the native CSS `@view-transition { navigation: auto; }` API to handle page morphing instead of JS libraries. 
- **Transition Fixes:** To prevent the 1:1 square tiles from stretching wildly when morphing into 16:9 hero banners, `object-fit: cover` and `contain: paint` were applied to the transitioning elements. 
- **Animation Conflicts:** Decided to remove `opacity: 0` entry animations from the `body` and `.hero-image` elements on case study pages, as they were conflicting with the View Transition API's snapshotting process (causing muddy crossfades instead of seamless expansions).
- **Video Edge Blending:** Instead of standard opacity changes, video backgrounds (`Scene.mp4`, `Scene2.mp4`) in tiles and hero sections use a combination of radial-gradient overlays and `-webkit-mask-image` with `backdrop-filter: blur` to create a "frosted vignette" effect, ensuring overlaid text remains highly legible.
- **Iframe Handling:** Case study iframes use `overflow: hidden` on wrappers and `width: 100%; height: 100%` on the iframe elements to fit containers dynamically and permanently eliminate native double scrollbars.
